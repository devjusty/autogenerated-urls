## Review Findings

### Critical (Must-Fix)
- [x] **CR-ITEM-1.1 [Unbounded attachment query can exhaust memory]**:
  - **Severity**: Critical
  - **Location**: `autogenerated-urls.php:123-130` (original issue)
  - **Description**: `get_posts` is called with `'posts_per_page' => -1` for attachments, loading all records into memory in one request. Large media libraries can cause high memory usage, slow admin responses, or fatal OOM.
  - **Recommendation**: Switch to batched retrieval (paged loop) and cache generated URL sets with transients/object cache. Add upper bounds and lazy-loading for very large datasets.

- [x] **CR-ITEM-1.2 [Collected URL list remains unbounded]**:
  - **Severity**: High
  - **Location**: `autogenerated-urls.php:31-45`, `63-176`
  - **Description**: Attachment retrieval is paged, but every generated URL is still accumulated in arrays and rendered in one admin response. Authors, categories, and tags are also retrieved without pagination. Very large sites can still hit response-size, memory, or execution-time limits.
  - **Resolution**: Authors, attachments, categories, and tags now retrieve and render 100 records per page, with shared admin pagination via the `agud_page` query argument. Date and CPT archive lists remain bounded by their naturally smaller archive sets.

### Warnings (Should-Fix)
- [x] **CR-ITEM-2.1 [Possible runtime warnings from WP_Error/false URLs]**:
  - **Severity**: Warning
  - **Location**: `autogenerated-urls.php:87`, `autogenerated-urls.php:92`, `autogenerated-urls.php:116`, rendered at `autogenerated-urls.php:52`
  - **Description**: `get_category_link` and `get_tag_link` may return `WP_Error`; `get_post_type_archive_link` may return `false`. Current code stores outputs directly and later runs `esc_url($url)` which expects string-like input. This can produce warnings and malformed output.
  - **Recommendation**: Guard every URL-producing call with `is_wp_error(...)` / strict truthiness checks and skip invalid entries.

- [x] **CR-ITEM-2.2 [N+1 query pattern for month archives]**:
  - **Severity**: Warning
  - **Location**: `autogenerated-urls.php:96-103`
  - **Description**: Code performs 1 query for years and then 1 additional query per year for months, causing N+1 DB round trips as data grows.
  - **Recommendation**: Replace with a single grouped query for year/month pairs (or use WordPress archive APIs where feasible), then build links from grouped results.

- [x] **CR-ITEM-2.3 [Reverse tabnabbing risk on external tab opens]**:
  - **Severity**: Warning
  - **Location**: `autogenerated-urls.php:52`
  - **Description**: Links use `target="_blank"` without `rel="noopener noreferrer"`, allowing opened pages to access `window.opener` in some environments.
  - **Recommendation**: Add `rel="noopener noreferrer"` to all `_blank` links.

- [x] **CR-ITEM-2.4 [Incorrect/non-canonical endpoint generation]**:
  - **Severity**: Warning
  - **Location**: `autogenerated-urls.php:20`, `autogenerated-urls.php:30`
  - **Description**: `home_url('/404')` is not a canonical WordPress 404 endpoint, and `home_url('/wp-json/')` can diverge from proper REST base behavior under custom setups.
  - **Recommendation**: Replace with descriptive non-link label for 404 behavior or a validation note; use `rest_url()` for REST root.

- [x] **CR-ITEM-2.5 [Potential key collisions hide entries]**:
  - **Severity**: Warning
  - **Location**: `autogenerated-urls.php:62`, `autogenerated-urls.php:76`, `autogenerated-urls.php:87`, `autogenerated-urls.php:92`
  - **Description**: Arrays are keyed by display/title/name strings. Duplicate labels overwrite earlier values silently, reducing completeness of output.
  - **Recommendation**: Use unique keys (e.g., include IDs/slugs in key) or store as list items with explicit `label` + `url` objects.

- [x] **CR-ITEM-2.6 [Date query ordering is not portable under DISTINCT]**:
  - **Severity**: Warning
  - **Location**: `autogenerated-urls.php:137-141`
  - **Description**: The grouped query selects year/month expressions with `DISTINCT` but orders by the unselected `post_date` column. MySQL configurations enforcing strict DISTINCT ordering may reject this query, leaving date archives empty or producing a database error.
  - **Resolution**: The query now orders by the selected aliases (`year_num DESC, month_num DESC`), which keeps the ordering columns in the result and avoids strict DISTINCT-ordering failures.

## Implemented Changes

The following findings from the original review are implemented in the current code:

- Attachment lookup uses one paged ID query instead of `posts_per_page => -1` (`autogenerated-urls.php:123-145`).
- High-volume author, attachment, category, and tag sections are limited to 100 results per page with admin pagination (`autogenerated-urls.php:34-45`, `65-99`, `101-176`).
- Category, tag, and CPT links reject `WP_Error`, `false`, and empty values before rendering (`autogenerated-urls.php:121-132`, `172-175`).
- Year/month archive discovery uses one grouped query, and month names use `wp_date()` (`autogenerated-urls.php:137-156`).
- Date archive pairs are ordered by the selected year/month aliases instead of the unselected `post_date` column (`autogenerated-urls.php:141`).
- New-tab links include `rel="noopener noreferrer"` (`autogenerated-urls.php:64-69`).
- REST root generation uses `rest_url()`, and the 404 item is clearly labeled as an example path (`autogenerated-urls.php:32-44`).
- Labels include IDs or post-type names where needed to avoid collisions (`autogenerated-urls.php:78`, `106`, `123`, `131`, `174`).
- Admin UI strings use the `autogenerated-urls` text domain and the repository includes a POT template (`autogenerated-urls.php:8-14`, `languages/autogenerated-urls.pot`).
